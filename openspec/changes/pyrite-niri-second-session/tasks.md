## 3. System-level session registration

- [ ] 3.1 Set `programs.niri.enable = true` in `modules/machines/nixos/pyrite/default.nix`, beside the existing GNOME/GDM block — verify: `nix eval .#nixosConfigurations.pyrite.config.services.displayManager.sessionData.sessionNames` returns `["gnome","niri"]`, and `nix eval .#nixosConfigurations.pyrite.config.services.displayManager.generic.environment.XDG_DATA_DIRS` contains the same store path `...config.services.displayManager.sessionData.desktops` evaluates to. That pair is the whole mechanism by which GDM sees a session: it arrives through `XDG_DATA_DIRS` on `display-manager.service`, not through `/run/current-system/sw/share/wayland-sessions`, which does not exist on this machine. `design.md` OQ3.
- [ ] 3.2 Set `services.displayManager.defaultSession = null` **explicitly**, in the same block, with a comment recording why the explicit null is not redundant: it is a plain definition and therefore beats nixpkgs' `mkDefault "niri"` at `programs/wayland/niri.nix:42`, whereas the option's own `null` default does not — verify: `nix eval .#nixosConfigurations.pyrite.config.services.displayManager.defaultSession` returns `null` **and** `nix eval --raw .#nixosConfigurations.pyrite.config.services.displayManager.generic.preStart` returns the empty string. The second half is the one that matters: a non-empty pre-start is `set-session <name>`, which rewrites every non-system user's AccountsService session on every display-manager start. `design.md` D4.
- [ ] 3.3 Confirm the choice of `null` over `"gnome"` is the one implemented — verify: `grep -n "defaultSession" modules/machines/nixos/pyrite/default.nix` shows `null`, and the comment names the alternative and why it was rejected (`"gnome"` also pins GNOME, but by rewriting every user's saved session on every start, which destroys the per-user memory the picker depends on).
- [ ] 3.4 Record that the session picker needs no option — verify: the comment cites gnome-shell's `js/gdm/loginDialog.js:388-390` at tag 50.2, `if (ids.length <= 1) { this._button.hide(); return; }`, so that a later reader does not go looking for a NixOS switch that does not exist.

## 4. The never-auto-suspend guarantee and explicit power-key policy

- [ ] 4.1 Carry an explicit `services.logind.settings.Login.IdleAction = "ignore"` so the property is declared rather than inherited from an upstream default — verify: `nix eval .#nixosConfigurations.pyrite.config.services.logind.settings.Login` shows `IdleAction = "ignore"` alongside the three existing lid keys, unchanged; and after deploy, `busctl get-property org.freedesktop.login1 /org/freedesktop/login1 org.freedesktop.login1.Manager IdleAction` on pyrite returns `s "ignore"`. The live value is already `ignore` today by systemd's own default (`logind.conf.xml:148-173` at v261); writing it makes it auditable. `design.md` D7.
- [ ] 4.2 Establish that nothing in the niri session starts an idle daemon — verify: after signing in to niri on the machine, `systemctl --user list-units --type=service --state=running` and `ps -u cameron` show no `swayidle`, `hypridle`, `gsd-power`, or other idle manager, and `systemctl --user list-units 'xdg-autostart*'` shows nothing active. This is the observation `design.md` D7 explicitly says the source reading does not supply: niri has no idle option in its configuration language at all (`git grep -i idle` over `niri-config/src/` at `v26.04` returns nothing) and implements only the notify and inhibit sides (`src/handlers/mod.rs:517-533`), but "no consumer of those notifications is running" has to be seen, not deduced.
- [ ] 4.3 Confirm no blanket suspend block was smuggled in as a substitute for D7/D9 — verify: `jj diff -- modules/machines/nixos/pyrite/default.nix` shows no `AllowSuspend`, no masked `sleep.target`, no logind inhibitor, and no change to `disable-d3cold-all`, `nvme-d3cold-suspend-guard`, `disable-lid-wakeup`, `boot.kernelParams`, or `HandleLidSwitch*`. D9's explicit `HandlePowerKey = "ignore"` is intended, not a violation of this task. Blocking suspend outright would also strand the three D21 units that exist to make a deliberate suspend survivable.
- [ ] 4.4 Declare `services.logind.settings.Login.HandlePowerKey = "ignore"` alongside the existing logind settings (D9) — verify by evaluation: `nix eval --raw .#nixosConfigurations.pyrite.config.services.logind.settings.Login.HandlePowerKey` returns `ignore`; `nix eval --raw '.#nixosConfigurations.pyrite.config.environment.etc."systemd/logind.conf".text'` contains `HandlePowerKey=ignore` in `[Login]`, with the lid keys unchanged. Check `HandlePowerKeyLongPress` remains unset or `ignore`; if unset, re-establish the evaluated systemd version's default as `ignore` (261.1 at authoring, `src/login/logind-core.c:51`). After activation inspect `/etc/systemd/logind.conf` and any drop-ins on pyrite for overrides before task 8.7. Do not use the deprecated `services.logind.powerKey` alias: it resolves but warns at this pin. Deliver this together with task 2.5, not as a choice between the two.
